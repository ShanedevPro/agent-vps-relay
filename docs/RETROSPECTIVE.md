# Anonymized lessons / 匿名经验总结

This is a generalized sequence, not a transcript or a claim that the same network behavior will occur elsewhere.

1. A VPS was provisioned and the services ran, but that did not establish usable client connectivity.
2. Controlled target/core/address-family comparisons showed that a REALITY target change restored an IPv6 path.
   A separate oversized-certificate parser problem was reproduced. Neither finding proved an entire address permanently blocked.
3. A different computer on the same campus was useful for isolation, but not an independent ISP comparison.
   A mobile test without IPv6 could not settle the original IPv6 question.
4. Both REALITY and Hysteria2 were accepted with native clients and actual browser checks. Short samples supported a daily choice,
   not a universal speed winner or long-term censorship/account-access guarantee.
5. An annual VPS migration required distinct purchase, allocation, identity, recovery, server and client gates. Fresh credentials were used.
6. The primary computer moved only after isolated testing and an independently executed recovery demonstration.
7. Administration then moved behind Tailscale while public TCP/UDP443 continued serving proxy clients.
8. Old cloud resources, client nodes, tailnet membership and tunnel jobs were retired separately; temporary tools were cleaned only after acceptance.

Why work took longer than an installation tutorial suggests:

- Transport failures were initially easy to confuse with protocol or client errors.
- Protocol/target/version changes without a fixed hypothesis make results hard to compare.
- Browser/session authentication, recovery-console readiness and OS privileges are real gates, not incidental clicks.
- An automation runner can open a port before being ready; a test harness failure must not count as a protocol failure.
- A scripted check accidentally using the working proxy can create a false success.
- A full page transfer timeout can coexist with useful HTTP connectivity; bounded probes and browser acceptance answer different questions.
- A streaming shell can continue after a failed statement. Use bounded scripts, explicit exit handling and post-operation readback.
- A stopped transient timer may unload its service. Inspect actual state rather than repeatedly stopping a nonexistent unit.

The reusable contribution is an ordered, evidence-based workflow with recovery and privacy—not a permanent list of magic domains or flags.

中文：安装成功不等于能用；同校园的两台电脑不等于不同网络；不同地址族不能直接互证。
先固定假设再对照测试，区分线路、协议、客户端和测试程序自身故障。
主机迁移、主客户端切换、管理收口和旧资源销毁分别验收；正常联网始终有独立退路。
